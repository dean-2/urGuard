urGuard

Post-Quantum Zero-Trust Messaging, Crash-Safe Key Governance & Explainable Access Guard

Track 4 · Zero AI/ML · Vetted PQC

Problem Statement

Classical encryption fails against harvest-now, decrypt-later quantum adversaries, while distributed key rotation and device revocation often break active transfers or silently desynchronize across nodes. Meanwhile, black-box anomaly detectors cannot explain why an alert fired or handle skewed clocks across microservices.

Unique Selling Proposition (USP)

  • Hybrid PQC E2E + Transport: X25519MLKEM768 TLS paired with per-message X25519 + ML-KEM-768, HKDF-SHA256, AES-256-GCM AAD binding, and ML-DSA-65 signatures.
  • Crash-Safe Multi-Node Governance: Atomic WAL two-phase rotation (30s grace), streaming CRL propagation, signed backups, and canonical SHA-256 audit logs.
  • Explainable Zero-AI Detection: Deterministic rules, EWMA baselines, ±30s watermark clock-skew buffer, and identity→service lateral-movement graph.

urGuard Threat Model & Verification Scope

Assets, Adversaries, Trust Boundaries, Assumptions & Explicit Non-Goals

Page 2 of 2

1. Protected Assets

  • Long-Term Identity Keys (IK_sig): ML-DSA-65 signing keypairs bound to user, service, and device identities.
  • Epoch & Ephemeral Session Keys (EK_epoch, SK_ephem): Hybrid X25519 + ML-KEM-768 keys; SK_ephem zeroized after session derivation/completion.
  • Shared DEKs & Encrypted Backups: Collaborator Data Encryption Keys re-encapsulated on device loss; Argon2id + HKDF / AES-256-GCM key bundles signed with ML-DSA-65.
  • Tamper-Evident Audit Log & Access Graph: Canonical JSON records chained via SHA256(seq || prev_hash || canonical_body) with signed checkpoints.

2. Adversary Capabilities

  • Harvest-Now, Decrypt-Later Quantum Adversary: Captures ciphertexts today and breaks classical KEMs or compromises post-session IK_sig / retired EK_epoch.
  • Active Network Attacker (MitM): Replays envelopes, modifies recipient_id or key_epoch, drops/reorders chunks, or hijacks ResumptionTicket tokens.
  • Compromised Device / Insider Pivot: Stolen enrolled device (device_old) or valid credentials traversing unseen service hops (edge-gateway → dev-service → secrets-vault).
  • Injection & Storage Tamper Attacker: Submits newline/JSON injection payloads or alters historical audit rows / backup ciphertext bytes.

3. Trust Boundaries

  • Console ↔ Control Plane: Nginx /api/ proxy + ConnectRPC; UI renders untrusted metadata strictly as plain text (no dangerouslySetInnerHTML).
  • Control Plane ↔ Relay Nodes: Mutual-authenticated X25519MLKEM768 TLS with runtime-generated ephemeral mTLS CA/leaf certs (never committed).
  • E2E Envelope vs. Transport: Application AES-256-GCM AAD binding + ML-DSA-65 signatures hold even if transport terminates at relays.
  • Untrusted Input ↔ Canonical Audit Core: User-supplied text stays isolated in escaped payload.metadata; WAL commits precede streaming acknowledgements.

4. Security Assumptions

  • Host RAM & OS CSPRNG are trusted before SK_ephem zeroization.
  • Clocks remain within ±30s default (±60s max tested); pairs inside 2 * skew flag order_uncertain: true.
  • Standardized Go crypto/mlkem, cloudflare/circl, and atomic WAL fsync.

5. Explicit Limits & Non-Goals

  • Active host RAM dumps / cold-boot attacks during live sessions are out of scope.
  • Clock drift exceeding ±60s degrades causal ordering guarantees.
  • Volumetric DoS and hardware side channels outside stdlib/circl.
  • Trojanized client binaries or compromised initial root bootstrap.
